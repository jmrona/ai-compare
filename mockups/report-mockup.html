Activity logger for user actions

Add an ActivityLogger that records user actions (login, logout, meal logged) with a timestamp and the user id, saves them in the existing SQLite database, and lets an admin list the last 50 entries. Context: we need this for the support team. When a user writes to support saying "my meals disappeared", the agent should be able to see what the user did in the last days without asking the user for screenshots. Requirements: - Use the existing database layer in src/db. Do not open a second connection. - Add a migration for the new table. Follow the naming of the existing migrations. - The logger must never make a user request fail. If writing the entry fails, log the error and carry on. - Keep the API small: log(userId, action, details?) and latest(limit = 50). - The admin listing goes under /admin/activity and must only be visible to admins. - Add tests next to the existing ones in tests/, using the in-memory SQLite helper. Out of scope: a UI for the listing, exporting entries, and deleting old entries. We will add retention later.
